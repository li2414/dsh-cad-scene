## 一、识别准确率提升（三层入手）

### 1.1 输入质量层——"喂给模型的特征决定上限"

| 措施 | 说明 | 预期收益 |
| --- | --- | --- |
| **聚类质量先行** | 大簇链式吞并（device_3 万图元巨簇）是最大噪声源 → 灵敏度滑杆 + 簇上限分裂 + 巨簇警告 | 高：识别对象干净了，其余手段才有效 |
| **文本深度清洗** | MTEXT 控制码剥离、全半角/单位归一、标注文本与设备的就近关联增强 | 中：evidence 质量直接受益 |
| **形状特征** | 长宽比、规则度、**阵列检测**（等距重复=货架排/输送段）、块名与 ATTRIB 属性（目前被过滤，实为型号信息金矿） | 高 |
| **拓扑特征** | 邻接关系（贴货架者=输送线、贯通全场者=主通道、孤立小件=AGV）——空间先验编码进 digest | 中 |
| **单位置信度** | 单位猜测从"启发式"升级为"尺寸×型号库反推"，标注在 digest 里 | 中 |

### 1.2 识别策略层——LLM 调用设计

| 措施 | 说明 |
| --- | --- |
| **两阶段识别** | ①粗分类（组级，便宜）→ ②细判定（仅歧义组/个例进第二轮，可带局部视图） |
| **自一致性投票** | 同组采样 3 次取共识，置信度=一致性——纯提示词工程，立竿见影 |
| **结构化校验层** | 输出 schema 校验 + 尺寸交叉校验（model size_hint × 拟合缩放 vs bbox，超容差自动降置信度）——拦住"看着像就报 0.9" |
| **多模态增强**（可选） | 歧义设备渲染局部俯视图 → 视觉模型看图判定；CAD 语义模糊时形状说话 |
| **分批与缓存** | 组级结果按图纸指纹缓存；同型图纸二次识别零成本 |

### 1.3 人工闭环层——准确率的最大来源

```
人工修正（改型号/剔除）→ 自动沉淀为「修正记录」
   ├─ 短期：注入下次识别的 few-shot 示例（越用越准）
   ├─ 中期：沉淀为业务规则表（"Robots-货架 一律 goodsShelf"），规则优先于 AI
   └─ 长期：形成企业设备知识库（型号特征 → 型号 的经验映射）
```

配套：识别结果的「待确认」队列 + 一键确认/修正的审核 UI（切片 C）。

## 二、三方服务评估

| 服务 | 判断 | 理由 |
| --- | --- | --- |
| **LLM 推理** | ✅ 不接三方 | 走 DSH 内置 `llm` 服务（现有 DeepSeek 路由）——成本可控、内网闭环，已验证可用 |
| **视觉大模型**（GLM-4V / Qwen-VL 等） | ⭕ 可选插拔 | 仅在"两阶段识别"的歧义判定步低频调用；按需计费，不进主链路 |
| CAD 云转换（Autodesk APS 等） | ❌ 不需要 | ODA 本地转换已工作（cnhd 实测）；数据不出内网 |
| 零件/型号目录 API | ❌ 不需要 | `device-models.manifest.json` 就是权威库 |
| Embedding 服务 | ⭕ 视 RAG 决策而定 | 见第三节；若上 RAG 可用内置 llm 的 embedding 或本地模型 |

**原则**：主链路（解析→识别→替换）零外部依赖；三方只做"可插拔增强"，任何一项失效都能降级运行。

## 三、RAG 与向量数据库：现阶段不需要，但要留接口

### 3.1 规模论证（决策依据）

| 数据 | 规模 | 检索方式 | 需要向量库？ |
| --- | --- | --- | --- |
| 型号库 | 34 款 | 全量塞提示词 ≈ 2KB | ❌ 天然全量 |
| 修正记录 | 预估百级 | 结构化规则表 + few-shot 全量注入 | ❌ 精确匹配更快更准 |
| 业务规则 | 十~百条 | 键值匹配（图层→型号） | ❌ |
| **设备手册/选型文档** | 未来千页级 PDF | 语义检索 | ✅ 这才是 RAG 的用武之地 |
| 历史图纸库 | 百张+ | 图指纹相似检索（复用绑定结果） | ✅ 二期价值大 |

**结论**：向量库的价值在"万级非结构化文本"。当前数据是结构化小集——上 RAG 等于用模糊语义检索替代精确键匹配，准确率不升反降、还引入运维负担。

### 3.2 架构预留（关键）

把"知识供给"做成可替换接口，现在与将来零成本切换：

```
识别提示词 = digest + 型号库 + [知识段]
                                    ▲
              现在：JSON 全量注入（规则表 + few-shot 修正记录）
              将来：RAG 检索注入（手册段落 / 相似图纸绑定结果）
```

### 3.3 将来启用 RAG 的技术预案（供决策）

- 向量库：**SQLite + sqlite-vec**（单文件、零运维，配本地面板场景）或 Chroma（独立服务）
- Embedding：内置 llm 的 embedding 模型，或本地 bge-m3（中文强）
- 语料：设备手册 PDF（先文本抽取+分块）+ 修正记录 + 图纸 digest
- 二期亮点：**图纸指纹 embedding**——新图纸检索最相似历史图纸，直接复用其绑定结果（识别成本趋近于零）

## 四、落地路线

| 阶段 | 内容 | 里程碑 |
| --- | --- | --- |
| **P0（本周）** | 聚类灵敏度 + 文本清洗 + 尺寸校验层 + 自一致性投票 | 识别准确率明显抬升，现有链路不动 |
| **P1（切片 B/C）** | 模型库+替换渲染（主线）；修正记录沉淀 + few-shot 注入；待确认审核 UI | 「越用越准」闭环成立 |
| **P2（规模化）** | 两阶段识别 + 可选视觉模型；若接手册/图纸库 → 启用 RAG（技术预案就绪） | 全自动批量识别 |

## 五、待拍板问题
